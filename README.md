# 大模型对比台

把各家大模型的**评分、价格、发展路线和关键文章**放在一处，全站由公开数据自动生成。
上线之后不需要任何人维护：一个每天定时运行的工作流抓取三个上游、合并成快照、重新渲染整站并发布。

当前快照：**425 款模型 / 26 家厂商 / 171 个渠道 / 3883 条报价**。

```bash
npm run pipeline   # 抓数据 → 画形象 → 渲染 → 体检
npm run serve      # http://127.0.0.1:3100
```

## 它回答什么问题

| 问题 | 在哪看 |
| --- | --- |
| 现在谁最强？各家的门面模型什么水平？ | 首页　`/` |
| 最新的模型现在卖多少钱？哪里买便宜？ | 价格与购买　`/pricing/`（**按发布时间倒序，最新在前**） |
| 智力和能力各维度排名、性价比、最便宜、最长上下文 | 排行榜　`/leaderboard/` |
| 这一代比上一代**具体**多了什么？凭什么？ | 模型详情　`/model/<slug>/` |
| 一家厂商的产品线是怎么演进的？ | 厂商页　`/vendor/<id>/` |
| 数据从哪来、怎么算的、为什么不用人管？ | 项目文档　[`docs/数据与方法.md`](docs/数据与方法.md)（**不上站**） |

## 需求对照

| 需求 | 实现 |
| --- | --- |
| 首页展示各厂商的评分、优点、输入输出价格 | 首页按「今日格局 / 各厂商门面 / 智力前十 / 最近发布」组织。评分取 Epoch AI 的 ECI 综合智力与 LiveBench 综合分；价格取 models.dev 的官方挂牌价；「优点」不是人工写的推荐语，而是由规格与成绩**推导**出来的 8 类结论（见下） |
| 点模型 → 完整发展路线图 + 关键文章，文章说明因此新增的能力 | 模型页的「发展路线图」把同一产品线按**世代**分组，每一代下面列出「与上一代相减后确实发生变化」的条目；「关键性文章」里的每篇都强制带一个 `unlocks` 字段，说明该模型因此新增了什么能力 |
| 每个模型的 Q 版形象 | 由快照**确定性合成**的 SVG（非位图、非手绘）。同一份数据永远画出同一张图，共 425 张，单张约 3 KB |
| 专门界面收集官方与第三方费用 + 跳转购买 | `/pricing/` **按发布时间倒序**，最新的模型排在最前面；上游没给发布日期的模型不猜顺序，单独列在最后。展开任意一行即摊开该模型的**每一条渠道**，标注「官方 / 云平台 / 第三方」，右侧直接给下单入口 |
| 上线后零人工维护 | `.github/workflows/sync.yml`，每天 UTC 20:10（北京 04:10）跑一次全流程并提交快照 |

## 数据从哪来

三个上游，各管一块，互不重叠：

| 上游 | 提供 | 许可 |
| --- | --- | --- |
| [Epoch AI](https://epoch.ai/data/ai-benchmarking-dashboard) | ECI 综合智力 + 59 个细分榜单 | CC-BY 4.0 |
| [models.dev](https://models.dev) | 模型规格、官方价格、各渠道报价 | MIT |
| [LiveBench](https://livebench.ai) | 逐任务得分 → 归并成 7 个能力大类 | Apache-2.0 |

还有一块是**人工策展**的、不在上面的自动化范围内：`src/content/papers.ts` 里的论文与发布文章。
每条都带一个 `unlocks` 字段写明「这款模型因此新增了什么能力」。
其中 arXiv 编号全部用 `export.arxiv.org` 的 API 核对过标题，官方链接只收录实测返回 200 的——
核不过的一律不收，宁可少一条也不放一个可能 404 的链接进去。

### 合并时会踩到的坑（都已处理）

三个上游对同一款模型的写法完全不同，直接按名字对齐会得到一堆重复和错配。归一化在 `scripts/sync/lib/keys.ts`：

- **版本号粘连**：`gpt-5-2` → `gpt-5.2`。这里有个隐蔽的陷阱——`llama-3-70b` 同样满足「数字-数字」，
  会被粘成 `llama-3.70b`，显示出来就是「Llama 3.70b」，把「第 3 代 70B 参数」读成了「3.70 这个版本」。
  必须让正则检查后面的单位字母（`b/m/k/t`）来区分。
- **日期戳**：`Deepseek V4 Pro 0813` 会在四家厂商名下各出现一次，要按 MMDD 后缀剥离后合并。
- **厂商归属**：云平台会托管别家的模型。若不加约束，Amazon Bedrock 下的 Claude 和 Llama
  会被算成「亚马逊发布的模型」。所以只把落在**自家产品线前缀**里的模型收作「发布」，
  托管的一律降级为「一条报价」。
- **放宽匹配**：上游经常一边写 `claude-opus-4.6`、另一边写 `claude-opus-4-6-latest`。
  匹配索引对每个键**双向登记**放宽形态，逐级降级查找，但只在唯一命中时才认。

## 三个「不做就等着出错」的设计

### 1. 零价不等于免费

上游有 240 多条报价的单价是 `0`，但它们**不是不花钱**，而是**不按 token 计价**：
阿里云百炼的 token 套餐、腾讯/智谱/MiniMax 的 coding plan、NVIDIA NIM 与 HuggingFace 的试用额度。

直接渲染成「$0」会同时错两次：读者以为模型白送，而任何「谁更便宜」的排序都会让一个
「$20/月不限量」的套餐以「$0/M」的身份排到所有真实按量价格前面。

处理方式是**保留但降级呈现**——它确实是真实存在的购买途径，用户就是想知道有没有包月的路子。
排序时排除，展示时标成「套餐/免费」。`scripts/verify.ts` 里有一条构建期检查专门守这个语义。

### 2. 低到不像真的价格，不当优惠宣传

约 2900 条第三方报价里，绝大多数**高于**官方价（转售要加价），这合理。
但有十几条只有官方价的 4%~19%，且高度集中在两家渠道、跨十几个不同模型都是同一个比例。

这种一致性说明它大概不是折扣，而是**计价口径不同**（共享号池、按字符计费、套餐折算）。
站点没法验证第三方的账单，所以既不删也不当优惠：单独标「存疑」，并且**不计入「最大价差」统计**，
也不参与「性价比」榜——否则 GPT-5.5 会凭空变成全站性价比第一。

### 3. 用分位，不用绝对阈值

「便宜」「上下文长」这类判断如果写死阈值（比如「< $1/M 算便宜」），会被时间腐蚀：
一年后所有模型都便宜了，标签就全废了。

所以全站所有强弱/贵贱判断都用**当前全体模型里的分位**，每个榜只在自己参赛的人群里算分位。
跨赛制的分数不混算。

### 合理性闸门

同步管线在写入前会过一次 `validate`：总数骤降超过 25%、ECI 覆盖率相对腰斩、
价格整批消失、出现负数价、slug 重复——任一条命中就**拒绝写入、保留旧快照、非零退出**。

这条闸门真的拦下过东西（厂商重组导致模型数 855 → 421 那次，核对确认是合法变更后才重置基线放行）。
它防的失效模式是：解析器一条都没接到，覆盖率静默掉到 0，页面照常渲染但所有排名都错了。

## 关于「零维护」的实际边界

自动化的是**数据**，不是**判断**。下面这几类东西仍然需要人：

- **新厂商的档案**：`src/content/vendors.ts` 里的中文名、配色、母题。上游出现新厂商时，
  没有档案也能跑（会走「wanderer」兜底），只是视觉上不那么讲究。
- **关键文章的 `unlocks`**：这个字段必须人来写。让模型去猜「这篇论文让模型新增了什么能力」，
  就会得到一段听起来很对、实际上没有依据的话——那正好违背了这个站存在的理由。
- **口径变更**：上游改字段名或下载地址时同步会失败并开 issue。有闸门和内建兜底之后，
  这类失败通常是**报错型**的，看得见——不像覆盖率静默归零那样危险。

上游挂掉时网站照常在线：同步和画形象两步都是 `continue-on-error`，失败只开 issue 留痕，不阻断发布。
已经生成好的静态页面继续服务上一版好数据。

## 目录

```
scripts/
  sync/            三源抓取、归一化、合并、闸门
    lib/           http（ETag 条件请求）· zip（自写解压，无依赖）· csv · keys（归一化）· match（模糊匹配）
    sources/       modelsdev.ts · epoch.ts · livebench.ts
    merge.ts       骨架 + 挂载 + 补录 + 去重
    validate.ts    合理性闸门
  avatars/         确定性 SVG 形象合成（母题表 + 状态配饰层）
  build.ts         渲染全站到 dist/
  verify.ts        产物体检：死链 / 渲染残留 / 零价语义 / 形象 / 搜索索引
  serve.mjs        本地预览（零依赖静态服务器）
  shot.mjs         整页截图（走 Chrome DevTools Protocol，便于人工过目）

docs/
  数据与方法.md     方法论说明。给项目内部阅读，不发布到站点

src/
  lib/types.ts     数据契约
  lib/snapshot.ts  读快照
  lib/derive.ts    标尺层（分位）· 优点推导 · 路线图世代引擎
  site/            css.ts · components.ts · layout.ts · pages.ts
  content/         厂商档案 · 渠道注册表 · 论文与发布
```

### 技术选型的说明

**零依赖**。数据管线直接用 `node --experimental-strip-types` 跑 TypeScript，Web 层是自己写 HTML 字符串，
没有任何运行时或构建依赖。这不是洁癖——最初是照着参考项目用 Next.js 起的，
但 `npm install` 卡在 sharp 等原生二进制的下载上二十分钟没动静，而本项目实际上不需要
任何需要编译的东西。去掉依赖之后：没有 lockfile 漂移，没有供应链风险面，CI 里没有 install 步骤，
构建 886 个文件耗时约 3.5 秒。

代价是 HTML 要手写转义、没有 JSX 的类型检查。对这个规模（7 类页面模板）是划算的，
再加上 `verify.ts` 在构建期兜住了链接和渲染残留，比类型系统更贴近实际会出的问题。

## 本地开发

```bash
node --version          # 需要 >= 22.18（用到 --experimental-strip-types 与全局 WebSocket）

npm run sync            # 抓三个上游（约 40s，走网络）
npm run avatars         # 由快照合成 425 张 SVG
npm run build           # 渲染到 dist/
npm run verify          # 体检，有问题就非零退出
npm run serve           # 本地预览
```

只需抓过一次数据之后，改样式或文案时可以只跑 `build` + `verify`，不必联网。

`SITE_URL=https://your.domain npm run build` 会额外生成 `sitemap.xml` 与 `robots.txt`。
不配就不生成——不猜一个域名写进去。

## 部署

推到 GitHub，在仓库 Settings → Pages 把 Source 设为 **GitHub Actions**，即可。

如果部署在**项目页**（`https://user.github.io/<repo>/`）而不是自定义域名或用户主页，
需要在 Variables 里设 `BASE_PATH=/<repo>/`，否则 404 页里的链接会指向错误前缀。

可选：`SITE_URL` 用于生成 sitemap。

### 无人值守的两个约定

- 同步失败时开一条带 `data-sync` 标签的 issue；同名 issue 只存在一条，后续失败追加评论，
  不会让邮箱被每天一条的告警刷屏。
- 快照本身有变更才会提交（`git diff --cached --quiet` 挡掉空提交），所以同步正常时
  仓库不会有噪声提交。

## 已知边界

- **ECI 覆盖率约一半**（206 / 425）。Epoch 只测一部分模型，未覆盖的模型在相关榜单上不参与，
  页面会显示「暂无综合评分」而不是编一个数出来。
- **LiveBench 只匹配上 43 款**。它的模型命名与 models.dev 差异最大，且榜单本身只收录约 58 款。
- **GitHub / HuggingFace 链接未收录**：本机抓取时这两个域名经代理不可达，
  无法实测 200，因此官方链接只收了能验证的那些。
- **报价是挂牌价**，不含优惠、批量和合约折扣，也不代表实际账单。页面有明确声明。
- 本站只做归集与换算，不参与任何交易、不收取佣金。
